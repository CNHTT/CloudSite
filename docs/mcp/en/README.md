# Bweb MCP Setup

Bweb exposes a standard **MCP Streamable HTTP** endpoint. Create a token and connect Claude Code, Codex, Workbuddy, Cursor, n8n or any MCP client to build, edit, publish and bind domains, then run inquiries, chat, subscriptions, email campaigns, social distribution and analytics — without a plugin or browser extension, and without locking you into any AI platform.

## Endpoint and authentication

```text
POST https://bweb.help/api/mcp
Authorization: Bearer cs_xxxxxxxx
Content-Type: application/json
```

- Transport: MCP Streamable HTTP with JSON-RPC 2.0, supporting `tools/list` and `tools/call`.
- For self-hosted instances, replace `https://bweb.help` with your site URL.
- Clients that only support local stdio can use the zero-dependency `cloudsite-mcp.mjs` bridge, which forwards JSON-RPC to the HTTP endpoint.

## Bring your own AI, no platform lock-in

Bweb does not dictate which model or client you use. MCP is an open protocol; once connected, your own AI decides how to call the tools:

| Client | How to connect |
| --- | --- |
| Claude Code / Codex / Workbuddy / Cursor / Claude Desktop | HTTP or stdio — either works |
| n8n / Make / Zapier | HTTP Request node calling `/api/mcp` directly |
| ChatGPT and other remote clients | Streamable HTTP + Bearer when the client supports remote MCP |
| Custom scripts / internal agents | Send JSON-RPC directly, or reuse `cloudsite-mcp.mjs` |

Built-in models power site generation, Agent tasks and on-site AI features. For operations, analytics, customer chat and marketing over MCP, you use your own AI. Switching clients never changes the tool list, scopes, site coverage, quotas or audit trail.

### Edit sites with your own tools too

Edit `index.html`, CSS and images locally with your own editor, scripts or AI tools, then let the MCP assistant upload the files:

| Your workflow | MCP call |
| --- | --- |
| Edit the full site locally | `create_upload_link` (ZIP, single-use link) or `upload_site` (small text sites), with `deploy=true` to publish in one step |
| Change a single file | `write_site_file`, then `deploy_site` |
| Generate or edit with the platform AI | `generate_site` / `chat_site` |
| Generated by other tools, needs inquiries and tracking | `enhance_embed_inject` to add `enhance.js` |

Preview with `preview_site`, then publish with `deploy_site`. A full upload replaces all existing files; preview links last 24 hours by default.

## Connect in five minutes

### 1. Create a token

Sign in to the [Bweb console](https://bweb.help) → **Settings → MCP / Agent**:

- **Read-write token** — build, generate, upload, edit, publish, bind domains, reply to chats, change settings and send campaigns.
- **Read-only token** — inspect sites and business data; `tools/list` never returns write tools, so it is safe to hand to an auditor.
- Tokens start with `cs_` and are **shown only once**; scope them to specific sites, set an expiry, and revoke them anytime.
- Create a separate token per client so each can be revoked independently.

### 2. Connect Claude Code (HTTP, recommended)

```bash
claude mcp add --transport http cloudsite https://bweb.help/api/mcp \
  --header "Authorization: Bearer cs_your_token"
```

Check with `claude mcp list`, or use `/mcp` in a session.

### 3. Connect stdio-only clients (Codex, Workbuddy, Claude Desktop and others)

```bash
curl -O https://bweb.help/cloudsite-mcp.mjs
```

Codex — add to `~/.codex/config.toml`:

```toml
[mcp_servers.cloudsite]
command = "node"
args = ["/absolute/path/cloudsite-mcp.mjs"]
env = { CLOUDSITE_URL = "https://bweb.help", CLOUDSITE_API_TOKEN = "cs_your_token" }
```

Workbuddy / Claude Desktop / Cursor style:

```json
{
  "mcpServers": {
    "cloudsite": {
      "command": "node",
      "args": ["/absolute/path/cloudsite-mcp.mjs"],
      "env": {
        "CLOUDSITE_URL": "https://bweb.help",
        "CLOUDSITE_API_TOKEN": "cs_your_token"
      }
    }
  }
}
```

### 4. Connect other HTTP clients

```json
{
  "mcpServers": {
    "cloudsite": {
      "type": "http",
      "url": "https://bweb.help/api/mcp",
      "headers": { "Authorization": "Bearer cs_your_token" }
    }
  }
}
```

Or send JSON-RPC directly:

```bash
curl https://bweb.help/api/mcp \
  -H "Authorization: Bearer cs_your_token" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": { "name": "list_sites", "arguments": {} }
  }'
```

### 5. Start with two questions

```text
capabilities   → token scope, available tools, membership, wallet balance and quotas
agent_guide    → recommended workflows, write-tool rules and safety guidance
```

Then just describe what you want:

> Use `create_site` to create "Acme Robotics" for industrial robot arms in English, then `generate_site` to build the pages.

> Upload `/path/to/site` as `my-site`, publish it with `deploy_site`, and bind `demo.example.com` with `bind_domain`.

> Run `enhance_seo_audit` on `my-site` with `mode=live`, then hand the fixes to `chat_site`.

> List yesterday's inquiries, mark them as contacted, and export October subscribers as CSV.

## Permissions and security

- **Least privilege** — read-only tokens only see read tools; write tools are absent from `tools/list` and return `scope_denied` if called directly.
- **Site scope** — tokens can cover all sites or specific `site_id`s; cross-site calls return `site_scope_denied`.
- **Explicit confirmation** — sending campaigns, activating automations, social dispatch and creating exports require `confirm=true` or an explicit confirmation string.
- **Credential isolation** — tools never return SMTP passwords, ESP API keys, site keys, Google secrets or raw tokens.
- **Audit** — every `tools/call` records token, tool, site, row count, IP and `request_id`; recent usage is visible in the console.
- **Rate limits** — reads 120/min/token, writes 60/min/token; exports, campaign sending and recharge have separate limits.
- **Same rules as the console** — MCP does not bypass plan quotas or business rules; tokens stop working immediately when membership expires, the account is disabled or the token is deleted.

## Long-running tasks and links

| Scenario | How |
| --- | --- |
| AI generation or edits take a while | Call `generate_site` / `chat_site` with `wait=false`, then poll `get_task` |
| Concurrency | Up to 2 long-running tasks per account; task results stay in memory for 30 minutes |
| Preview | `preview_site` returns a public signed link, valid for 24 hours by default (1–72 hours) |
| ZIP upload | `create_upload_link` returns a single-use upload URL valid for 30 minutes by default (5–120 minutes) |

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `401` / invalid token | Check the full token, whether it was revoked, and whether the account is active |
| `403` / read-only token | The token is read-only; use a read-write token |
| `402` / membership expired | Renew in the console and retry |
| Generation or edit times out | Use `wait=false` + `get_task`, or raise the client tool timeout |
| Upload returns `413` | Raise the reverse-proxy body limit (e.g. Nginx `client_max_body_size`) |
| Upload link already used | Upload links are single-use; call `create_upload_link` again |
| Bridge script produces no output | Run `CLOUDSITE_API_TOKEN=... node cloudsite-mcp.mjs` manually; errors go to stderr |
